# 语音识别助手（Chrome 插件）

自动找出网页中**所有 `<audio>` 播放器**，在每个播放器下方加一个「语音识别」按钮。
点击按钮后，插件把该播放器的音频文件以 `file` 字段 POST 到你自己的识别接口，并把接口返回的内容追加显示在播放器下方。

## 功能

- **全自动注入**：不需要填写 XPath、不需要逐条添加规则，页面里每个 `audio` 都会自动出现按钮。
- **自动定位播放源**：依次尝试 `currentSrc`、`src` 和 `<source src>`，兼容 `blob:` / `data:` 音频。
- **动态页面支持**：SPA 切换、滚动加载、按钮动态新增的播放器都会在出现后自动补上按钮。
- **结果就地展示**：接口返回的文本追加在播放器下方；若响应带逐词时间轴，还会渲染成「序号 / 文字 / 开始 / 结束」表格，文本可一键复制。
- **后台转发请求**：由插件后台发出请求，不受页面跨域（CORS）限制，接口地址只保存在本机。

## 安装

1. 打开 Chrome，地址栏输入 `chrome://extensions/`。
2. 打开右上角的「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本项目文件夹（包含 `manifest.json` 的目录）。
4. 建议把插件固定到工具栏，方便打开设置。

## 配置

点击工具栏中的插件图标，在弹窗里填写：

| 配置项 | 说明 |
| --- | --- |
| 启用开关 | 关闭后页面中的按钮会立即移除 |
| 接口地址 | 你的识别接口完整地址，例如 `http://localhost:8000/api/asr` |
| 文件字段名 | 上传音频时使用的表单字段名，默认 `file` |

弹窗顶部还会显示当前页检测到的 `audio` 数量，点「重新检测」可手动重新扫描。

## 接口约定

插件点击按钮时会发出如下请求：

```
POST <接口地址>
Content-Type: multipart/form-data; boundary=...

file=<音频文件二进制>
```

- 音频字段名可在弹窗里修改（默认 `file`）。
- 文件名会尽量沿用原始地址中的文件名，识别不出扩展名时按 `Content-Type` 补 `.mp3` / `.wav` / `.m4a` 等。
- 响应为 `2xx` 视为成功：
  - 返回纯文本 → 直接展示；
  - 返回 JSON → 依次尝试 `text`、`transcript`、`asr_text`、`sentence`、`result`、`content`、`data`、`message` 等常见字段，找不到时展示格式化前的原始 JSON。
- 若响应里带逐词时间轴（`timestamps`，兼容 `timestamp` / `words` / `tokens` / `segments` / `items`），结果区会在全文下方渲染表格：

  | 序号 | 文字 | 开始 | 结束 |
  | --- | --- | --- | --- |
  | 1 | 我 | 0.84s | 0.90s |

  表格最大高度 260px，超出可滚动，表头吸顶；`start` / `end` 支持数字秒、`"0.84"`、`"00:00:01.234"` 三种写法。参考 `demo/res.json`。
- 响应里的 `filename`（文件名）和 `elapsed`（接口耗时）会显示在结果标题行。
- 响应为其他状态码视为失败，会显示 `HTTP 状态码` 和服务端返回内容。
- 请求超时时间 180 秒；音频上限 100MB（`blob:` / `data:` 音频在页面内读取，上限 20MB）。

> 如果你的接口需要鉴权，可以写在接口地址的查询参数里（例如 `?token=xxx`），或后续在 `background.js` 的请求头中补充。

## 使用

1. 打开任意包含 `audio` 的网页（例如 `demo/test.html`）。
2. 播放器下方会出现紫色「语音识别」按钮。
3. 点击按钮 → 按钮显示「识别中…」→ 接口返回后，全文与逐词时间轴表格追加显示在按钮下方。
4. 结果右上角有「复制」按钮，可直接复制识别文本。

## 测试页

`demo/test.html` 包含 4 个场景：mp3、wav、`<source>` 写法、动态添加的播放器。

直接双击以 `file://` 打开时，需要在 `chrome://extensions/` 的插件详情里开启「允许访问文件网址」；也可以在项目目录执行 `python -m http.server 8000`，然后访问 `http://localhost:8000/demo/test.html`（推荐）。

## 说明与限制

- 不作用于 `chrome://` 页面、Chrome 应用商店等浏览器内置页面。
- `iframe` 内的 `audio` 暂不支持（只注入顶层页面）。
- 使用封闭 Shadow DOM 的播放器无法匹配（只扫描普通 DOM 中的 `audio`）。
- 安装插件前已经打开的页面需要刷新一次才会出现按钮。
- 若播放器是「隐藏 audio + 自定义 UI」的实现，按钮会出现在隐藏的 `audio` 标签所在位置，而不是自定义 UI 下方。
- 接口地址与字段名保存在 `chrome.storage.local`，只在本机生效，不会随 Chrome 账号同步。

## 文件结构

```
manifest.json     扩展清单（Manifest V3）
content.js        内容脚本：扫描 audio、注入按钮、提交识别、展示结果
background.js     后台服务：下载音频、POST 到接口、解析响应
popup.html        弹窗结构（接口设置、页面状态）
popup.css         弹窗样式
popup.js          弹窗逻辑：读写配置、检测页面 audio 数量
demo/test.html    本地测试页
demo/res.json     接口返回示例（含 timestamps，用于对照表格展示）
```
